# AI_CONTEXT — Постоянная память проекта WildWestGunslinger

## Назначение

Папка `AI_CONTEXT` служит постоянной памятью AI-ассистента при работе над проектом WildWestGunslinger. Все файлы в этой папке содержат проверенные факты о проекте, текущее состояние, правила и задачи.

## Файлы

| Файл | Назначение |
|------|-----------|
| `PROJECT_STATE.md` | Технические характеристики проекта, платформы, основные параметры |
| `ARCHITECTURE.md` | Фактическая архитектура AI-системы, связи между компонентами |
| `RULES.md` | Постоянные правила работы с проектом |
| `CURRENT_TASK.md` | Текущая задача и её статус |
| `CONFIRMED_STATE.md` | Список подтверждённых работающих систем |
| `CHANGELOG.md` | Хронология изменений AI-разработки |
| `ART_PIPELINE.md` | Blender / 3D asset production мост (art focus, workflow, QA) |
| `VERIFICATION.md` | Проверка перед завершением: evidence-правила, запрет self-reported PASS |
| `DEBUGGING.md` | Систематическая отладка: воспроизведение → evidence → гипотеза → фикс → перепроверка |
| `SPEC_IDEAS.md` | Применимые идеи Spec Kit без установки, поверх существующего workflow |

## Зоны ответственности

- `AI_CONTEXT` отвечает за Unity / project state.
- `.opencode/skills/wwg-character-art/SKILL.md` отвечает за character-art quality rules. Не копировать SKILL в AI_CONTEXT; ссылаться.

## Workflow

```
АНАЛИЗ → ПЛАН → СОГЛАСОВАНИЕ ПОЛЬЗОВАТЕЛЯ → ИЗМЕНЕНИЕ → COMPILE → UNITY TEST → ПОДТВЕРЖДЕНИЕ ПОЛЬЗОВАТЕЛЯ
```

### Порядок действий

1. **АНАЛИЗ** — прочитать `AI_CONTEXT`, изучить код, найти точные ссылки на методы/поля.
2. **ПЛАН** — описать что будет изменено, какие файлы затронуты, какие методы.
3. **СОГЛАСОВАНИЕ** — показать план пользователю и получить явное одобрение.
4. **ИЗМЕНЕНИЕ** — внести изменения только после одобрения.
5. **COMPILE** — проверить отсутствие ошибок компиляции.
6. **UNITY TEST** — пользователь тестирует в Unity.
7. **ПОДТВЕРЖДЕНИЕ** — пользователь явно подтверждает работоспособность.

### Ключевое правило

**Ничего нельзя считать подтверждённым только потому, что код компилируется или AI считает работу завершённой. Подтверждение даёт пользователь после тестирования в Unity.**

## Правила использования

- **Перед изменениями** — читать `AI_CONTEXT`, понять текущее состояние.
- **После существенных изменений** — обновлять соответствующие MD-файлы.
- **Не переписывать** работающие системы без обоснованной причины.
- **Не создавать** новые AI-состояния или AI-скрипты без явного согласования с пользователем.
- **Не удалять** код/файлы без разрешения пользователя.
- **Учитывать** целевые платформы: Android + Windows.
- **Избегать** создания дубликатов классов и скриптов.
- **Разделять** статусы: implemented → compiled → tested → confirmed.
